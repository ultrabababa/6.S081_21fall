Q: Which other xv6 system call(s) could be made faster using this shared page? Explain how.

在xv6中，通过共享只读页（如USYSCALL页）加速系统调用的核心思路是将频繁读取的内核数据暴露到用户空间，避免陷入内核的模式切换开销。除了已实现的getpid()，以下系统调用也可通过类似机制优化：

​gettimeofday() 获取当前时间
​优化原理​：时间值通常频繁读取但极少修改（如每毫秒更新一次）。在共享页中维护一个由内核定期更新的时间戳（如struct { uint64 sec; uint64 usec; }），用户进程直接读取该地址即可
。
​优势​：避免为获取时间频繁陷入内核（如高频日志记录场景）。
​uptime() 查询系统运行时长
​优化原理​：系统启动时间在运行期间恒定不变。在共享页中存储启动时间戳（boot_time），用户程序通过current_time - boot_time计算运行时间
。
​注意事项​：需内核在定时器中断中更新current_time字段，确保用户空间读到最新值。
​sbrk() 的堆指针查询
​优化原理​：sbrk(0)仅查询当前堆顶地址而不分配内存。在共享页中维护进程内存布局（如struct { uint64 heap_start; uint64 heap_end; }），用户可直接读取堆边界
。
​限制​：仅优化查询操作，实际分配内存仍需调用完整sys_sbrk。
​进程统计信息（如getrusage）​​
​优化原理​：将只读的进程统计信息（如页错误计数、上下文切换次数）放入共享页。用户监控工具（如top）可直接读取无需为每个指标单独调用内核。
